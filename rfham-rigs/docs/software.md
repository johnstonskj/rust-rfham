# Ham Radio CAT / CI-V Software Catalog

A reference catalog of desktop and mobile software that talks to amateur radio
transceivers via CAT (Yaesu/Kenwood/Elecraft-style) and/or CI-V (Icom)
computer-control protocols. Compiled 2026-07-23. Companion to the manuals in
`cat/`, `civ/`, `downloads.md`, and `quirks.md` in this directory.

Each entry notes whether it is built on a shared rig-control **library**
(Hamlib, Omni-Rig, FlexLib, etc.) or implements CAT/CI-V natively — see the
[Libraries](#libraries) section for details on those underlying components.

---

## Radio Controllers

General-purpose GUIs and engines whose primary job is driving a real
transceiver via CAT/CI-V (as opposed to logging or APRS tools that merely
read rig state — see those sections below for overlap notes).

- **[Hamlib / rigctl / rigctld](https://hamlib.github.io/)** — Classification: Radio Controller, Utility/Protocol Tester. Platform: Linux, Windows, macOS (library + CLI tools). Protocol: CAT + CI-V, protocol-agnostic — Hamlib itself implements the backends for both. Radio scope: Multi-vendor, broadest support of any tool in this catalog (hundreds of rig backends). Library: **is** the library (see Libraries section) — `rigctl`/`rigctld` are its bundled command-line control/daemon front ends. [Supported rigs list](https://github.com/Hamlib/Hamlib/wiki/Supported-Radios).
- **[FLRig](https://www.w1hkj.org/)** (W1HKJ) — Classification: Radio Controller. Platform: Windows, macOS, Linux. Protocol: CAT + CI-V (native per-rig drivers). Radio scope: Multi-vendor (Yaesu, Icom, Kenwood, Elecraft, Ten-Tec, and more via its own rig driver classes). Library: direct/native CAT-CI-V implementation, no shared library — exposes its own XML-RPC server (port 12345) that other apps (fldigi, WSJT-X, JTDX, N1MM+) use as a control broker. [Homepage / docs](https://www.w1hkj.org/).
- **[Ham Radio Deluxe (HRD)](https://www.hamradiodeluxe.com/)** — Classification: Radio Controller, Logging/APRS Reader. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor (Yaesu, Icom, Kenwood, Elecraft, FlexRadio, Ten-Tec). Library: native per-rig CAT/CI-V implementation (no Hamlib/Omni-Rig dependency). [Rig Control feature page](https://www.hamradiodeluxe.com/features/rigcontrol/) / [CAT commands docs](https://support.hamradiodeluxe.com/support/solutions/articles/51000052482-cat-commands). See also Logging section (HRD Logbook).
- **[DXLab Suite — Commander](http://www.dxlabsuite.com/commander/)** — Classification: Radio Controller. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor (Alinco, Elecraft, FlexRadio, Icom, JRC, Kachina, Kenwood, Ten-Tec, Yaesu) — controls up to 4 rigs at once. Library: native/direct implementation; other DXLab modules (DXKeeper, etc.) get rig state from Commander rather than talking to the radio themselves. [Download/setup page](http://www.dxlabsuite.com/commander/download.htm).
- **[Omni-Rig](https://dxatlas.com/OmniRig/)** (Afreet Software / VE3NEA) — Classification: Radio Controller, *also a Library* (see Libraries section). Platform: Windows (32/64-bit COM component). Protocol: CAT + CI-V via per-rig `.ini` description files. Radio scope: Multi-vendor, extensible by end users writing new `.ini` rig files. Library: is itself the shared library many Windows apps (Log4OM, QLog, SDR-Console, N1MM+ add-ons, etc.) link against for CAT control.
- **[OpenHPSDR PowerSDR](https://github.com/TAPR/OpenHPSDR-PowerSDR)** (TAPR, community-maintained) — Classification: Radio Controller. Platform: Windows. Protocol: CAT (Kenwood-style command emulation) for third-party app interop; native internal control of OpenHPSDR/Flex-1000-5000-era hardware. Radio scope: Single product line (HPSDR/early FlexRadio Ten-Tec Hermes-class SDR transceivers). Library: direct/native implementation; exposes a CAT command layer (see [CAT Command Reference](https://github.com/TAPR/OpenHPSDR-PowerSDR/blob/master/Documentation/Radio/PowerSDR-CAT-Command-Reference-Guide-V3.docx)) so third-party loggers can treat it like a Kenwood rig. Appears to have slow/limited ongoing maintenance (legacy hardware focus).
- **[SmartSDR](https://www.flexradio.com/software/smartsdr/)** (FlexRadio Systems) — Classification: Radio Controller. Platform: Windows (SmartSDR for Windows), macOS/iOS (SmartSDR for Mac/iOS, App Store). Protocol: Native FlexRadio TCP/UDP API, plus a Kenwood-style **CAT emulation layer** for legacy third-party software. Radio scope: Single manufacturer (FlexRadio FLEX-6000/8000/Aurora series). Library: native implementation; Windows client and third-party integrations are built on **FlexLib** (see Libraries). [SmartSDR CAT User Guide](https://www.flexradio.com/documentation/smartsdr-cat-user-guide-pdf/).
- **[AetherSDR](https://github.com/aethersdr/AetherSDR)** — Classification: Radio Controller. Platform: Linux, macOS, Windows (Qt6/C++20, open source). Protocol: CAT via rigctld emulation and virtual-serial CAT; native FlexRadio protocol underneath. Radio scope: Single manufacturer (FlexRadio FLEX-6000/8000/Aurora), an open-source alternative to SmartSDR for non-Windows users. Library: implements its own rigctld-compatible CAT layer (Hamlib-protocol-compatible, not linked against Hamlib itself). Actively developed as of 2026.
- **[SDR-Console](https://www.sdr-radio.com/)** (Simon Brown, G4ELI) — Classification: Radio Controller. Platform: Windows. Protocol: CAT (serial) + CI-V, plus its own network protocol for synchronizing an external SDR with a real transceiver. Radio scope: Multi-vendor, broad SDR hardware support (Airspy, SDRplay, Perseus, LimeSDR, RTL-SDR, etc.) plus external radio sync via CAT/CI-V/Omni-Rig. Library: supports Omni-Rig as one control path alongside its own native serial CAT/CI-V driver. [External Radio Synchronisation docs](https://www.sdr-radio.com/external-radio).
- **[wfview](https://wfview.org/)** — Classification: Radio Controller, Utility/Protocol Tester. Platform: Windows, Linux, macOS (open source, Qt-based); community/experimental mobile builds. Protocol: CI-V only (also bridges to Kenwood-style rigctld for interop). Radio scope: Icom (and some Kenwood) network/USB-capable rigs (IC-7300, IC-7610, IC-705, IC-9700, IC-R8600, etc.) — an open-source alternative to Icom's own RS-BA1. Library: native CI-V implementation; itself exposes a [Hamlib rigctld-compatible emulation layer](https://wfview.org/wfview-user-manual/hamlib-rigctld-emulation/) plus a pseudo-terminal/virtual-serial CI-V passthrough for other apps to share the bus.
- **[Win4IcomSuite](https://icom.va2fsq.com/)** (VA2FSQ) — Classification: Radio Controller. Platform: Windows. Protocol: CAT/CI-V over USB or LAN. Radio scope: Single manufacturer, specific high-end Icom models (IC-7100, IC-7300, IC-7600, IC-7610, IC-7700, IC-7850/51, IC-9700, IC-7760, IC-705). Library: native implementation; provides 6 virtual-radio ports so third-party apps (HRD, DXLab, N1MM+, Log4OM) can share one physical CAT/CI-V connection.
- **[Win4YaesuSuite](https://yaesu.va2fsq.com/)** (VA2FSQ) — Classification: Radio Controller. Platform: Windows. Protocol: CAT. Radio scope: Single manufacturer (Yaesu FTDX1200/3000/5000/9000, FT-991/991A). Library: native implementation with the same virtual-port sharing model as Win4IcomSuite.
- **[Win4K3Suite / Win4K4Suite](https://va2fsq.com/)** (VA2FSQ) — Classification: Radio Controller. Platform: Windows. Protocol: CAT. Radio scope: Single manufacturer (Elecraft K3, K3S, KX3, KX2, K4) plus companion Elecraft accessories (P3 panadapter, KPA500, KAT500, KXPA100). Library: native implementation; interfaces third-party apps (HRD, DM780, DXLab, N1MM+) through virtual ports. [Third-party integration docs](https://va2fsq.com/third-party-software-and-hardware-integration/).
- **[N4PY Software (per-rig control apps)](http://www.n4py.com/)** — Classification: Radio Controller. Platform: Windows. Protocol: CAT + CI-V (separate dedicated program per radio family). Radio scope: Multiple manufacturers, but each product targets one rig family (Icom IC-7300/7610/9700, Yaesu FT-991/FTDX series, Elecraft K3/KX2/KX3, etc.) rather than being one universal app. Library: native per-rig implementation; also integrates panadapter and Winkeyer support. *(Site uses an older TLS/cert configuration that some HTTPS clients reject — verify in a standard browser if the link appears to fail.)*
- **[grig](https://groundstation.sourceforge.net/grig/)** — Classification: Radio Controller, Utility/Protocol Tester. Platform: Linux (GTK+/GNOME). Protocol: CAT + CI-V, protocol-agnostic via Hamlib. Radio scope: Multi-vendor (whatever Hamlib supports, including `rigctld` over the network). Library: **uses Hamlib** directly as its backend — a GUI front end to `rigctl`. Appears to have low/no recent development activity (long-idle SourceForge project) but still packaged in most Linux distros.
- **[RigCtldGUI](https://github.com/dl1ycf/RigCtldGUI)** (DL1YCF) — Classification: Radio Controller, Utility/Protocol Tester. Platform: Linux, macOS (MacPorts), Windows. Protocol: CAT + CI-V, protocol-agnostic via Hamlib. Radio scope: Multi-vendor (Hamlib-supported rigs). Library: **uses Hamlib** — bundles/builds Hamlib and wraps `rigctld` with a graphical front end so other apps (fldigi, WSJT-X, logging programs) can connect via TCP.
- **[CatBkt (Universal CAT Control)](https://www.maniaradio.it/en/catbkt.html)** (IZ2BKT) — Classification: Radio Controller. Platform: Windows (also runs under Wine on Linux). Protocol: CAT + CI-V, protocol-agnostic via Hamlib. Radio scope: Multi-vendor (Hamlib-supported rigs). Library: **uses Hamlib** (LGPL); also offers a DDE server for interop with MultiPSK, DXLab Suite, fldigi, and JT65-HF.

## Logging Software

Logbook applications whose CAT/CI-V integration is primarily to auto-fill
frequency/mode (and sometimes control the rig directly) while logging QSOs.

- **[Logger32](https://www.logger32.net/)** (K4CY) — Classification: Logging/APRS Reader, Radio Controller. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor, wide range of transceivers and rotators via serial/USB. Library: native per-rig implementation (no Hamlib/Omni-Rig dependency).
- **[N3FJP Amateur Contact Log (ACLog)](https://www.n3fjp.com/help/righelp.html)** — Classification: Logging/APRS Reader. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor (per-radio CAT command tables configured in the Rig Interface dialog, including CI-V address entry for Icom). Library: native implementation. N3FJP also publishes 20+ contest-specific logging programs sharing the same rig-interface engine. [Extended Rig Control guide (PDF)](http://www.n3fjp.com/help/CWRIYAESU.pdf).
- **[DXKeeper](http://www.dxlabsuite.com/dxkeeper/)** (DXLab Suite) — Classification: Logging/APRS Reader. Platform: Windows. Protocol: CAT + CI-V (indirectly). Radio scope: Multi-vendor. Library: does not talk to the rig itself — gets frequency/mode from the DXLab Suite's **Commander** module (see Radio Controllers), which does the native CAT/CI-V work.
- **[CQRLOG](https://www.cqrlog.com/)** — Classification: Logging/APRS Reader, Radio Controller. Platform: Linux (MySQL/MariaDB-backed). Protocol: CAT + CI-V, protocol-agnostic via Hamlib. Radio scope: Multi-vendor (140+ Hamlib-supported radio types). Library: **uses Hamlib** (`rigctld`/`rpc.rigd`).
- **[QLog](https://www.qlog.hamradio.cz/)** — Classification: Logging/APRS Reader, Radio Controller. Platform: Windows, macOS, Linux (Qt/SQLite, open source, GPLv3). Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: **uses Hamlib**, and also supports **Omni-Rig** and FlexRadio's TCI protocol as alternate rig-control paths — one of the few tools offering a choice.
- **[Xlog](https://xlog.nongnu.org/)** — Classification: Logging/APRS Reader. Platform: Linux (GTK+2). Protocol: CAT + CI-V, protocol-agnostic via Hamlib. Radio scope: Multi-vendor (Hamlib-supported). Library: **uses Hamlib** for frequency/mode/signal-strength readback. Development has been quiet for some years — appears to have low ongoing maintenance, though still packaged in major Linux distros.
- **[Swisslog](https://hb9tzu.ch/en/Swisslog/)** (originally HB9BJS, now maintained by EA3GCV) — Classification: Logging/APRS Reader. Platform: Windows. Protocol: CAT. Radio scope: Multi-vendor. Library: native implementation, with the ability to instead take frequency/mode from DX Lab Commander, FLRig, or Ham Radio Deluxe if those are already running.
- **[RUMlogNG](https://machamradio.com/blog/category/rumlogng/)** (DH1NGP/DF3CB era, currently maintained) — Classification: Logging/APRS Reader, Radio Controller. Platform: macOS (also iOS/iPadOS release history). Protocol: CAT + CI-V, including a dedicated Icom IC-7300 control panel with LAN support. Radio scope: Multi-vendor. Library: native implementation (Mac Ham Radio community also documents a separate "Cat-relay for macOS" tool for sharing one CAT port among several Mac apps). Actively updated (v6.4, 2026).
- **[MacLoggerDX](https://www.dogparksoftware.com/MacLoggerDX.html)** (Dog Park Software) — Classification: Logging/APRS Reader, Radio Controller. Platform: macOS. Protocol: CAT + CI-V. Radio scope: Multi-vendor, 100+ radio models (Elecraft, Kenwood, Icom, Yaesu, Ten-Tec, JRC, Drake, SDR platforms). Library: native serial/TCP drivers, plus explicit interop with **DXLab Commander**, **wfview**, and **Hamlib `rigctld`** as alternate control paths.
- **[Log4OM (v2)](https://www.log4om.com/)** — Classification: Logging/APRS Reader. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor. Library: user's choice of **Hamlib** or **Omni-Rig** as the CAT backend (Omni-Rig reported by the developer/community as the more stable option). [Quick Start Guide (PDF)](https://www.log4om.com/log4om/usermanual/Log4OM_Quick_Start.pdf).
- **[N1MM Logger+](https://n1mmwp.hamdocs.com/)** — Classification: Logging/APRS Reader, Radio Controller (contest logger). Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor (extensive supported-radio list, including older Icoms via a CT-17-style CI-V interface). Library: native per-rig serial drivers; also documented to work through **FLRig** as a shared CAT broker when running alongside other software. [Supported Radios](https://n1mmwp.hamdocs.com/manual-supported/supported-radios/) / [Interfacing guide](https://n1mmwp.hamdocs.com/setup/interfacing/).
- **[WriteLog](https://writelog.com/)** — Classification: Logging/APRS Reader, Radio Controller (contest logger). Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor — WriteLog advertises the largest number of built-in rig drivers of any contest logger. Library: native per-rig drivers (see [Rig Drivers notes](https://writelog.com/notes/rig-drivers)); also offers its own "WriteLog Remote Control" feature.

## Digital Mode Software

Software whose primary purpose is a digital operating mode (FT8/FT4/JT65/PSK/etc.), but which drives the rig via CAT/CI-V (almost always through Hamlib or a Hamlib-compatible broker) to track/set frequency for the mode.

- **[WSJT-X](https://wsjt.sourceforge.io/wsjtx.html)** (K1JT et al.) — Classification: Radio Controller (rig-control client), Logging/APRS Reader (has QSO logging). Platform: Windows, macOS, Linux. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: **uses Hamlib** directly (per-rig dropdown), or can be pointed at **FLRig**, **DXLab Commander**, **Ham Radio Deluxe**, or **Omni-Rig** as an external CAT broker via its "Hamlib NET rigctl" option. [User Guide](https://wsjt.sourceforge.io/wsjtx-doc/wsjtx-main-2.6.1.html).
- **[JTDX](https://sourceforge.net/projects/jtdx/)** — Classification: Radio Controller, Logging/APRS Reader. Platform: Windows, macOS, Linux. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: forked from WSJT-X and **uses its own maintained fork of Hamlib** (`jtdxhamlib`, [github.com/jtdx-project/jtdxhamlib](https://github.com/jtdx-project/jtdxhamlib)); can also share a port via FLRig.
- **[MSHV](http://lz2hv.org/mshv)** (LZ2HV) — Classification: Radio Controller, Logging/APRS Reader. Platform: Windows, Linux. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: **uses Hamlib** ("NET rigctl" support) alongside its own direct rig-interface settings. *(Note: the site's TLS certificate does not match its hostname in some strict clients — the content itself is the genuine, long-standing MSHV/LZ2HV site.)*
- **[fldigi](https://www.w1hkj.org/)** (W1HKJ) — Classification: Radio Controller, Logging/APRS Reader. Platform: Windows, macOS, Linux. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: supports **FLRig**, **Hamlib**, its own "RigCAT" native XML-defined driver, or plain RTS/DTR/GPIO PTT — user's choice of backend. [Xcvr Control Configuration docs](https://www.w1hkj.org/FldigiHelp/rig_config_page.html).
- **[VarAC](https://www.varac-hamradio.com/)** — Classification: Radio Controller. Platform: Windows (Wine-compatible on Linux/macOS). Protocol: CAT + CI-V. Radio scope: Multi-vendor via a community-maintained CAT command file. Library: supports **CAT** (its own native text/hex command engine), **RTS/DTR**, **Omni-Rig**, **FLRig**, or **Hamlib** — most flexible backend choice of the digital-mode tools. [Rig control / CAT command file guide](https://www.varac-hamradio.com/rig-control-file).

## Radio Simulators

Software that emulates a rig's CAT/CI-V interface, for developing or testing control software without real hardware.

- **[Hamlib Dummy Rig (model 1 / "Dummy")](https://github.com/Hamlib/Hamlib/wiki/Supported-Radios)** — Classification: Radio Simulator. Platform: Wherever Hamlib runs (Linux, Windows, macOS). Protocol: Emulates the generic Hamlib rig API rather than wire-level CAT/CI-V bytes. Radio scope: N/A — synthetic "rig" that accepts all Hamlib commands and returns benign canned responses, for exercising client applications (`rigctld -m 1` or `rigctld -m 2` for the "NONE" variant). Library: part of Hamlib itself.
- **[IC746CAT](https://github.com/kk4das/IC746CAT)** (KK4DAS) — Classification: Radio Simulator. Platform: Arduino (any MCU with a serial UART — Nano, Nano Every, etc.), used as a small hardware/firmware CI-V emulator. Protocol: CI-V only, emulating an Icom IC-746. Radio scope: Single simulated rig, but reported to work as a stand-in with WSJT-X, fldigi, Ham Radio Deluxe, Hamlib's `rigctl`, and the CatBkt universal CAT tool — useful for bench-testing CI-V clients without a real Icom radio. A fork, [IC746CAT_IC-701](https://github.com/Phoenix-64/IC746CAT_IC-701), adapts it for IC-701 emulation.
- **[iu2frl-civ "fake" transceiver mode](https://github.com/iu2frl/iu2frl-civ)** — Classification: Radio Simulator, *also a Library* (see Libraries section). Platform: Any Python 3 environment. Protocol: CI-V only. Radio scope: Simulates any CI-V-addressable Icom rig — the library's `fake=True` constructor flag prints CI-V bytes to the console instead of a serial port, and a bundled `fake_generic.py` script fakes a transceiver connection for automated build validation/testing.

## Utilities / Protocol Testers

Diagnostic tools, terminals, and bus monitors built for testing CAT/CI-V rather than full-time operating.

- **[rigctl](https://hamlib.github.io/) (Hamlib CLI)** — Classification: Utility/Protocol Tester, Radio Controller. Platform: Linux, Windows, macOS. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: bundled with Hamlib; `rigctl -l` lists all supported models/backends and is a common first troubleshooting step for verifying Hamlib rig-model numbers.
- **[rigctld](https://github.com/Hamlib/Hamlib/blob/master/doc/man1/rigctld.1)** — Classification: Utility/Protocol Tester, Radio Controller. Platform: Linux, Windows, macOS. Protocol: CAT + CI-V, protocol-agnostic. Radio scope: Multi-vendor. Library: the Hamlib network daemon (TCP port 4532 by default) that lets multiple client programs share one physical CAT/CI-V connection — used both as production glue and as a lightweight bus monitor/tester (`rigctld -v` verbose logging).
- **[grig](https://groundstation.sourceforge.net/grig/)** — see Radio Controllers section (dual-listed: also useful as a quick Hamlib connectivity tester).
- **[RigCtldGUI](https://github.com/dl1ycf/RigCtldGUI)** — see Radio Controllers section (dual-listed: bundles a Hamlib build/test harness).
- **[OmniRig BetaTest / Tester's Guide](http://dxatlas.com/omnirig/BetaTest.txt)** — Classification: Utility/Protocol Tester. Platform: Windows. Protocol: CAT + CI-V. Radio scope: Multi-vendor (whatever Omni-Rig `.ini` files exist). Library: companion test harness for Omni-Rig itself, used by the community to validate new/updated rig `.ini` description files before they're adopted.

## Manufacturer Remote-Control Utilities

First-party software from Icom, Kenwood, Elecraft, and Yaesu for controlling their own radios (often over IP/Bluetooth for remote-station use), plus the leading open-source alternative.

- **[Icom RS-BA1 (Version 2)](https://www.icomamerica.com/lineup/options/RS-BA1_Version2/)** — Classification: Radio Controller, Utility/Protocol Tester. Platform: Windows. Protocol: CI-V over IP (LAN/Internet) and USB. Radio scope: Single manufacturer, specific network-capable Icom transceivers (IC-7610, IC-9700, IC-705, IC-7300, etc.). Library: Icom's own native IP-CI-V implementation; not Hamlib-based. [Firmware/download page](https://www.icomjapan.com/support/firmware_driver/3460/).
- **[wfview](https://wfview.org/)** — see Radio Controllers section. Widely described by users and its own documentation as the leading free/open-source alternative to RS-BA1. [Comparison with RS-BA1](https://forum.wfview.org/t/comparison-with-rs-ba1/1189).
- **[Kenwood ARCP / ARHP (Advanced Remote Control/Host Program) series](https://www.kenwood.com/i/products/info/amateur/ts_890/arcp890_e.html)** — Classification: Radio Controller. Platform: Windows. Protocol: CAT, tunneled over TCP/IP for remote operation (ARHP runs on the "host" PC connected to the radio; ARCP is the remote "control" client). Radio scope: Single manufacturer, one program pair per radio family — ARCP/ARHP-480 (TS-480), ARCP/ARHP-590 (TS-590/590G), ARCP/ARHP-890 (TS-890S), ARCP-2000 (TS-2000). Library: native Kenwood implementation.
- **[Elecraft K3/K3S/KX3/K2 Utility programs](https://elecraft.com/pages/k3-k3s-kx3-and-k2-control-setup-programs)** — Classification: Radio Controller, Utility/Protocol Tester. Platform: Windows (some Mac/Linux options via third parties, linked from the same page). Protocol: CAT. Radio scope: Single manufacturer (Elecraft K3/K3S/KX3/K2/K4 family) — used for firmware updates, calibration, and configuration in addition to basic control. Library: native Elecraft implementation; Elecraft's own page candidly labels these as free but largely "unsupported, contributed utilities." [Firmware & Software index](https://elecraft.com/pages/firmware-software).
- **[Win4IcomSuite / Win4YaesuSuite / Win4K3Suite / Win4K4Suite](https://va2fsq.com/)** — see Radio Controllers section; effectively third-party (but manufacturer-endorsed/linked, e.g. from Elecraft's own utility page) manufacturer-specific control suites.
- **[N4PY per-radio control software](http://www.n4py.com/)** — see Radio Controllers section; another long-running third-party, single-manufacturer-per-product control-software line, also linked from Elecraft's own utility page.

## APRS Software

Clients for the Automatic Packet Reporting System whose CAT/CI-V integration is generally for reading/logging radio frequency state, not full rig control.

- **[APRSIS32 (APRSISCE/32)](http://aprsisce.wikidot.com/)** (KJ4ERJ) — Classification: Logging/APRS Reader. Platform: Windows. Protocol: N/A for its core APRS-IS/RF function; includes a Frequency Monitor window that can track/log a radio's current frequency. Radio scope: N/A (general APRS client; frequency-tracking integration is informal/manual rather than a documented Hamlib/Omni-Rig CAT backend). [Manual (PDF)](http://k5nx.com/information/aprs/APRS-IS-32_for_Windows/APRSIS32-Manual.pdf).
- **[UI-View32](https://www.ui-view.net/)** (G4IDE) — Classification: Logging/APRS Reader. Platform: Windows. Protocol: N/A (packet/TNC-based APRS client; no documented CAT/CI-V rig-control integration). Radio scope: N/A. **Appears unmaintained** — original author became a Silent Key in 2004; registration fees were waived posthumously and the software has had no further official development since, though a community groups.io list keeps informal support alive.
- **[Xastir](https://github.com/Xastir/Xastir)** — Classification: Logging/APRS Reader. Platform: Linux, BSD, macOS (X11-based, open source). Protocol: CAT, protocol-agnostic via Hamlib, used to read/log rig frequency for the "Interface Properties → Hamlib Model" setting. Radio scope: Multi-vendor (Hamlib-supported). Library: **uses Hamlib**. Note: the project's own `xastir.org` homepage/wiki has a history of intermittent downtime; the [GitHub repository](https://github.com/Xastir/Xastir) is the more reliable current reference.
- **[YAAC (Yet Another APRS Client)](https://www.ka2ddo.org/ka2ddo/YAAC.html)** (KA2DDO) — Classification: Logging/APRS Reader. Platform: Windows, Linux, Raspberry Pi OS, macOS, FreeBSD (Java, cross-platform, open source, LGPL). Protocol: Primarily TNC/AX.25-based; not documented as having a dedicated Hamlib/CAT rig-frequency-tracking backend the way Xastir does. Radio scope: N/A (general-purpose APRS client/I-Gate/digipeater). Included here as a well-known cross-platform APRS client for completeness, even though its CAT integration is minimal/undocumented compared to Xastir.

## Mobile Apps

iOS/Android apps that control rigs via CAT/CI-V, typically over Bluetooth, Wi-Fi, or USB-OTG.

- **[Icom RS-MS1i (iOS) / RS-MS1A (Android)](https://apps.apple.com/us/app/rs-ms1i/id1193842632)** — Classification: Radio Controller. Platform: Mobile (iOS 16+, Android). Protocol: CI-V over Bluetooth (via Icom's optional Bluetooth units, e.g. UT-137, UT-133). Radio scope: Single manufacturer, specific D-STAR-capable models (ID-4100A/E, ID-52 series, ID-5200 series, IC-705). Library: Icom's own native implementation. [Icom product page](https://www.icomamerica.com/lineup/options/RS-MS1I/).
- **[SDR-Control for Icom (iPhone/iPad/Mac)](https://apps.apple.com/us/app/sdr-control-for-icom/id1592313285)** (Roskosch / Black Cat Systems ecosystem) — Classification: Radio Controller. Platform: Mobile (iOS 17+, iPadOS), Desktop (macOS 14+, Apple Silicon and Intel — sold as a separate app). Protocol: CI-V over the Icom network/Wi-Fi interface. Radio scope: Single manufacturer, specific network-capable Icoms (IC-705, IC-7610, IC-9700, IC-7760, IC-R8600, IC-7300 MK2). Library: native implementation, a proprietary alternative to RS-BA1/wfview built specifically for Apple platforms. [Developer site](https://documents.roskosch.de/sdr-control-mac/).
- **[PocketRxTx](https://www.yo3ggx.ro/pocketrxtx/doc30/i.html)** (YO3GGX) — Classification: Radio Controller. Platform: Mobile (Android). Protocol: CAT, tunneled over the network via the companion **jAReC** server. Radio scope: Multi-vendor (whatever the paired jAReC/Hamlib-backed desktop instance supports), with bidirectional audio. Library: relies on jAReC (Java, runs on Windows/Linux/Mac/Raspberry Pi) as the desktop-side bridge to the physical rig — PocketRxTx itself is a thin remote client. Free and paid ("Pro," $3.95) tiers exist.
- **[FT8CN](https://github.com/N0BOY/FT8CN)** (N0BOY) — Classification: Radio Controller, Logging/APRS Reader. Platform: Mobile (Android). Protocol: CAT, over USB-OTG, Bluetooth, or Wi-Fi depending on the rig. Radio scope: Multi-vendor (implements its own per-rig CAT command sets; community-reported to work with e.g. Yaesu FT-857D). Library: native implementation; runs FT8/FT4 decode/encode natively on-device (no PC required) rather than piggybacking on WSJT-X. Open source. A more actively developed fork/rewrite exists as [FT8AF](https://github.com/patrickrb/FT8AF) (Jetpack Compose UI, English localization).
- **[D72-RigCTRL](https://github.com/DL1XY/D72-RigCTRL)** (DL1XY) — Classification: Radio Controller. Platform: Mobile (Android via USB-OTG), Desktop (Windows/cross-platform). Protocol: CAT (Kenwood-style command set specific to this handheld). Radio scope: Single manufacturer, single model (Kenwood TH-D72 dual-band handheld). Library: native implementation, open source.
- **[wfview (mobile/remote use)](https://wfview.org/)** — see Radio Controllers section. No dedicated phone app, but its client/server architecture is commonly run with a lightweight remote-desktop or VNC-style mobile client pointed at a `wfview` server; the project's own docs describe [remote operation](https://wfview.org/older-user-manual-pages/remote-operation/) patterns that mobile users rely on.

## Libraries

Shared components other applications link against or shell out to, rather than end-user applications in their own right. Most of the "Radio Controller"/"Logging" entries above note which of these (if any) they use.

- **[Hamlib](https://hamlib.github.io/)** — Classification: Library. Platform: Linux, Windows, macOS (C library with SWIG bindings for C++, Python, Perl, Tcl, Lua; also ported to Android — [android/README.android](https://github.com/Hamlib/Hamlib/blob/master/android/README.android)). Protocol: CAT + CI-V, and the closest thing to a universal abstraction layer in the ham radio world — "protocol-agnostic" for any of its dozens of supported backends. Radio scope: Broadest of any project cataloged here (hundreds of transceiver/receiver/rotator/amplifier backends). This is the library most other entries in this document mean when they say "uses Hamlib." [GitHub source](https://github.com/Hamlib/Hamlib) / [supported radios](https://github.com/Hamlib/Hamlib/wiki/Supported-Radios) / [Python bindings readme](https://github.com/Hamlib/Hamlib/blob/master/bindings/README.python).
- **[Omni-Rig](https://dxatlas.com/OmniRig/)** (Afreet Software / VE3NEA) — Classification: Library (also ships a usable Radio Controller GUI — see that section). Platform: Windows only (COM component). Protocol: CAT + CI-V via per-rig `.ini` description files. Radio scope: Multi-vendor, extensible via community-contributed `.ini` files; used by 50+ Windows applications per the developer's own claim (Log4OM, QLog, N1MM+ ecosystem tools, SDR-Console, VarAC, and many contest/logging programs).
- **[FlexLib](https://www.flexradio.com/api/developer-program/)** (FlexRadio Systems) — Classification: Library. Platform: Windows (.NET DLL); source available for porting. Protocol: Native FlexRadio TCP/UDP API (command/control/status plus panadapter/waterfall/meter/audio streaming) — not CAT/CI-V itself, but the layer that SmartSDR's own CAT-emulation sits on top of. Radio scope: Single manufacturer (FlexRadio FLEX-6000/8000/Aurora). FlexRadio's own Windows SmartSDR client is built on FlexLib, and third-party developers use it directly for tighter-than-CAT integration. [SmartSDR v4.x API (FlexLib) page](https://www.flexradio.com/software/smartsdr-v4-x-api-flexlib/).
- **[node-hamlib](https://www.npmjs.com/package/node-hamlib)** — Classification: Library. Platform: Node.js on Linux (designed for Raspberry Pi; compiles via node-gyp against `libhamlib-dev`). Protocol: CAT + CI-V, protocol-agnostic (thin wrapper). Radio scope: Multi-vendor (whatever the linked Hamlib supports). Early-stage/work-in-progress (v0.0.7) but actively referenced by hobbyist Node-based ham radio projects (e.g. rigbot, a Discord bot for `rigctld`).
- **[omnipyrig](https://pypi.org/project/omnipyrig/)** (4Z1KD) — Classification: Library. Platform: Windows (Python 3, wraps the Omni-Rig COM component via `win32com`). Protocol: CAT + CI-V, via whatever Omni-Rig `.ini` files are installed. Radio scope: Multi-vendor (same scope as Omni-Rig itself). Beta-status but functional; lets Python scripts drive a rig through Omni-Rig without writing raw COM code.
- **[iu2frl-civ](https://github.com/iu2frl/iu2frl-civ)** (IU2FRL) — Classification: Library (also usable as a Radio Simulator — see that section). Platform: Any Python 3 environment (cross-platform). Protocol: CI-V only, native implementation (not Hamlib-based). Radio scope: Icom-only; tested against IC-7300, IC-7300 MKII, IC-706 MKII, IC-821H, but designed to generalize to any CI-V-addressable Icom rig. Includes a `fake=True` simulation mode for development without hardware.
- **[pycom (siyka-au)](https://github.com/siyka-au/pycom)** — Classification: Library. Platform: Any Python environment. Protocol: CI-V only, native implementation. Radio scope: Icom-only; developed for and tested on the IC-AC120E airband receiver, but built as a general CI-V library usable with other Icom CI-V rigs.
- **[icom-lan (morozsm)](https://github.com/morozsm/icom-lan)** — Classification: Library. Platform: Any Python environment. Protocol: CI-V over Icom's native LAN (UDP) protocol — explicitly *not* Hamlib- or wfview-based. Radio scope: Icom-only, network-capable models. Useful for developers who want direct LAN control without running wfview or RS-BA1 as an intermediary.

## Notes on scope and gaps

- **rigctl/rigctld/grig/RigCtldGUI/CatBkt** are deliberately cross-listed across Radio Controllers and Utilities/Protocol Testers, since in practice they're used for both purposes — see the "see Radio Controllers section" pointers rather than duplicated full entries.
- **Ham Radio Deluxe** and several other tools genuinely span Radio Controller + Logging classifications; they are written up once (in Radio Controllers) with a cross-reference from Logging, per the task's guidance to avoid confusing duplication.
- Several manufacturer "cloning"/programming utilities (e.g. Icom's CS-705, Yaesu's ADMS programming software, Kenwood's MCP programmer) were intentionally excluded: they write memory-channel configuration to the radio over a serial link but are not CAT/CI-V control/logging/simulation/testing tools in the sense this catalog targets.
- The Elecraft K3/K4 Programmer's Reference and other protocol manuals referenced by this software are already cataloged in `downloads.md`.
